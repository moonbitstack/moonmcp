struct
pub struct Server { info : @types.Implementation instructions : String? ttl_ms : Int32 scope : Scope

An MCP server: the tools, resources, resource templates and prompts it offers, and who it says it is. It speaks both eras of the protocol. A request carrying its protocol version in _meta is served statelessly under the 2026-07-28 revision; an initialize request opens the handshake of the revisions before it. The same server is reached over Streamable HTTP with to_asgi, over stdio with run_stdio, or by any transport of your own through handle. ttl_ms and scope are the caching hints every list result carries under the 2026-07-28 revision. The presets say "stale at once" and "this caller only", the cautious end of both, since a server that changes what it lists per caller would otherwise leak one caller's list to the next.

fn
pub async fn Server::serve_lines(Self, async () -> String?, async (String) -> Unit) -> Unit

Serve newline-delimited JSON-RPC: read a line with read until it gives None, answer it, and write the reply as one line (← the stdio transport, over any pair of streams). A line that is not JSON is answered with a parse error; a blank one is skipped. Requests are worked on as they arrive, each in a task of its own, so a slow tool does not hold up the next call. Replies still leave in the order their requests came in, which is what a client that counts lines expects; a subscription's notifications are the exception, since they are not replies to anything. notifications/cancelled withdraws the request it names, which the running task sees through its context.

pub async fn Server::serve_subscription(Self, @json.Json, Map[String, @json.Json], Channel, cancellations? : Cancellations, queue? : @aqueue.Queue[@json.Json]) -> Unit

Serve one subscriptions/listen request until the transport lets go: the acknowledgement first, then every notification the filter asked for, each tagged with the id of the request that opened the stream. The reply to the request itself is sent by the caller when this returns, and only when it returns of its own accord: a stream cut by the transport has no reply, as the specification has it.

fn
pub fn Server::to_asgi(Self, path? : String, origins? : Array[String], docs? : String?, theme? : @docs.Theme, auth? : @auth.Bearer) -> async (@spec.Scope, async () -> @spec.Event, async (@spec.Event) -> Unit) -> Unit

The server as an ASGI application serving the MCP endpoint at path. Run it with mooncat, or mount it beside a moonapi app. Every message is its own POST, answered with one JSON object, or 202 for a notification. Sessions, the GET stream and DELETE belong to the revisions before 2026-07-28 and are optional there; this server keeps no session, so GET and DELETE answer 405. A 2026-07-28 request that offers a progress token, or that opens a subscription, is answered with text/event-stream when the client accepts it: the notifications the handler sends arrive on that stream, and the reply ends it. A request whose Origin header names another site is refused with 403, as the transport requires against DNS rebinding. An origin passes when its host is the request's own Host, a loopback address, or one listed in origins. docs names the path the documentation page is served at, beside the endpoint: a browser opened on it lists what the server offers and calls it, in both eras of the protocol. It is on at /docs unless told otherwise, as an API framework's interactive docs are; docs=None leaves it off, and a path equal to the endpoint's is ignored. theme picks its look, the moonmcp website's by default. The page carries no credentials of its own.

struct
pub struct Bearer {

How a transport checks a bearer token (← the authorization section of the protocol): a request without one is answered 401 with a WWW-Authenticate challenge, and one whose token does not verify is answered the same way with invalid_token. Two ways to build one: Bearer::hmac for a token signed with a shared secret, which is what a test and a single-tenant deployment use, and Bearer::own for anything else — an RSA or ECDSA key, a JSON Web Key Set fetched from the issuer, an opaque token looked up in a table. own takes the whole decision, so this library never has an opinion about how a token is judged, only about what happens when it is not.

pub struct Caching {

Answers a call from memory when the same call was made recently. The key is the operation, the name and the arguments, with object keys sorted at every depth, so a client that sends the same arguments in another order still gets the stored answer. Errors and asks for client input are never stored: repeating them would hide the reason and replay a state the client has already answered. ttl_ms is how long an answer stays good — five minutes, the default of MCP's cache. capacity is how many answers are kept before the oldest goes; shared says whether one caller's answer may be handed to another, which is only safe when the answer does not depend on who asked.

pub struct RateLimiting {

A token bucket per caller. Each caller starts with a full bucket of burst tokens, spends one per call, and gains rate tokens a second up to that ceiling. A caller with none left is refused with refused_code and told how long to wait; the bucket keeps no token for them, so a caller that keeps asking only waits longer. Ten a second, twenty at once, is MCP's default. The caller is the subject the authorisation check named, and everyone unauthenticated shares one bucket — give key to count by a header or a tool instead. clock reads seconds from any fixed origin; the default is the monotonic clock.
