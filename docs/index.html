Armillary · MCP framework

Model Context Protocol servers for MoonBit.

Register tools, resources and prompts, then serve them over Streamable HTTP or stdio. One server answers both protocol eras, so a client of either connects without configuration.

$moon add moonbitstack/moonmcp
scroll · the armillary

Capabilities

Three kinds, three colours.

Every capability is one component with the same lifecycle: register it, list it, call it, get a typed result back.

Tools
jade · #mcp.tool

A handler, an input schema, and a typed result. A wrong argument or an error the handler raises comes back as an isError result the model can correct from.

Resources
amber · #mcp.resource

A URI and a reader. A template puts {id} in the URI; each matching read runs the function with the variable read as its MoonBit type.

Prompts
amethyst · #mcp.prompt

A renderer that turns arguments into the messages a client hands to its model. Its parameters become the prompt's arguments.

A call

One call, four moves.

01

Discover

The client lists what the server offers: tools, resources, templates and prompts.

02

Call

It sends a name and arguments. The arguments are checked against the input schema before the handler runs.

03

Result

The handler's JSON returns as content; an error returns as isError, not a protocol fault.

04

Notify

A notification is a one-way wave: it leaves the server and expects no reply.

Two eras at once

Both revisions at once

A request that names 2026-07-28 in _meta is handled statelessly; initialize, and any request without it, falls back to the handshake (2025-11-25 back to 2024-11-05).

Two ways to speak

Streamable HTTP & stdio

to_asgi hands a moonasgi app to mooncat: one POST per message, origin-checked against DNS-rebinding. run_stdio speaks line-delimited JSON on native stdio.

Two ways to write

Register, or annotate

Call server.tool(name, handler, input_schema=…) by hand, or mark a function #mcp.tool and let the generator write the same registration, with the JSON Schema from the argument types.

Errors, not faults

Results the model can read

A wrong argument or an error the handler raises returns as a result marked isError, which the model reads and corrects from. Only a tool that does not exist is a protocol error.
